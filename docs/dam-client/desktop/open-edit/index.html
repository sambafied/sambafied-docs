Open, reveal, edit and check out

Guide home · Coverage and gaps · Image plan

Development guide draft, reviewed 28 October 2026. Steps describe the approved contract and are conditional on the installed build advertising that capability. Product and target acceptance remain separate.

Choose the command matching your purpose. Open obtains bytes for viewing; Edit creates a reviewed editing route; Reveal locates an item; Check out reserves ownership only where supported. Saving in Photoshop or another editor stays local until the publication action is accepted. Do not assume the file association, checkout request, editor launch and remote upload are one atomic operation.

Related-file downloads, external applications and Explorer paths need their own acceptance evidence. If a route is disabled, use the explicitly supported alternative or wait for qualification; a mock button is not evidence of native launch or drag success.

W08​

Open and Open With​

Documentation: FULL. Before you start: Have the associated desktop application and an eligible verified original.

Procedure. Select Open to obtain the original and launch its Windows association. Use Open With only where offered for the installed build. Wait for transfer completion before assuming the application received a usable file.

Expected result. Open is for viewing and does not imply checkout or publication. A launch success is separate from a successful download.

Cancel, errors and recovery. If no application is associated or launch fails, keep the downloaded bytes and use Reveal. Use Edit for planned changes; cancellation of a fetch never marks an incomplete original ready.

W09​

Edit, save locally and publish deliberately​

Documentation: FULL. Before you start: Choose an editable asset and inspect its lock owner and remote observation.

Procedure. Choose Edit and review whether checkout is requested or advisory-only behavior is being used. Open the verified original in the desktop editor. Save in that editor, then return to Edited locally. Review the saved generation before using Upload Changes.

Expected result. Save keeps work on this PC. Upload Changes is a separate publication decision. Checkout alone does not prove remote overwrite safety.

Cancel, errors and recovery. If another user owns checkout, the remote revision changed, or save tracking is uncertain, keep local bytes and inspect the conflict/recovery state. Cancel an Edit review without releasing someone else's lock.

W10​

Reveal the right folder​

Documentation: FULL. Before you start: Know whether you need the connected work folder, a managed cache location or an exported copy.

Procedure. Choose Reveal for the selected asset or folder, or Show work folder for the connection root. Confirm the location shown in Explorer. When a cache-specific action is needed, use its explicit managed-cache control; do not substitute another directory with a similar name.

Expected result. Explorer names may be edited without changing remote asset identity. Stable paths matter for linked documents.

Cancel, errors and recovery. If an item is cloud-only, allow its qualified fetch first. A missing/unsupported native work folder is not permission to unregister or recreate a retained root. Keep the current path and ask for recovery support.

W11​

Drag assets in or out​

Documentation: PARTIAL. Before you start: The installed build must have native drag-and-drop qualification for this route.

Procedure. For drag-out, select eligible originals and review the native drag plan; only start the drag after required files are ready. For drag-in, review the intended DAM destination and import inventory before authorizing publication.

Expected result. A visual drag gesture alone is not an upload or proof of correct native file custody.

Cancel, errors and recovery. Cancel an unaccepted drop without mutation. Inaccessible paths, external reparse points and unsupported shell routes must refuse clearly. Use explicit Open/Upload File while native drag acceptance is unfinished.

Remaining documentation gate. Native shell/application matrix and final drag gestures need accepted screenshots and tests.

W31​

Check out or check in separately​

Documentation: FULL. Before you start: Inspect current checkout owner and whether enforcement is advisory.

Procedure. Use Check out only when reserving an asset independently of Edit. Verify the returned ownership state. Use Check in only after reviewing local changes and any publication result. Confirm that the expected original owner/revision still applies.

Expected result. Check-in releases ownership; it does not upload saved bytes. A committed upload can remain checked out if its dependent check-in fails.

Cancel, errors and recovery. Do not override another owner. If lock status changes or a request outcome is unknown, inspect the original operation and retain local work.
