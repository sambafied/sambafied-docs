Connections, sign-in and sessions

Guide home · Coverage and gaps · Image plan

Development guide draft, reviewed 28 October 2026. Steps describe the approved contract and are conditional on the installed build advertising that capability. Product and target acceptance remain separate.

Use the Connections page to identify the server and account before acting. The active connection banner should show enough information to distinguish production from a local test environment. Separate connections can use independent identities. A remembered server and a remembered sign-in are different settings.

The production sign-in implementation and its qualified profile determine whether the Author page or external browser flow is used. See authentication decision and shell contract; do not promise a specific live SaaS flow based on the mock. Never collect a user's password in a support screenshot. Renewals must not silently open background MFA or switch an operation to another principal.

W01​

Manage named connections​

Documentation: FULL. Before you start: Have the Author URL, intended deployment, DAM root and permission to access it.

Procedure. Open Connections and choose the add/setup action. Enter a distinct name, deployment and Author origin; review the DAM root. Connect, then confirm the displayed principal before opening assets. Edit the Explorer display name through the connection controls; a display name is not a new remote identity. Before removing a connection, review its pending work and retained work folder.

Expected result. Each connection retains its own identity, work folder and job ownership. Switching connections does not redirect accepted work.

Cancel, errors and recovery. Correct an invalid origin/root before retrying. Cancel setup without publishing. Removal must preserve dirty files and recovery records; do not remove a Windows root manually.

W02​

Sign in and remember a session​

Documentation: PARTIAL. Before you start: Use a connection whose authentication profile has been approved for that deployment.

Procedure. Choose Sign in and complete the displayed Author or browser flow. Inspect the connected principal and connection name. Select Remember sign-in only when you intend protected retention for this connection. Use Cancel while authorization is pending to leave that attempt.

Expected result. Connected means identity has been verified; a remembered Author address alone does not mean credentials are remembered.

Cancel, errors and recovery. If login is denied, expires or the browser cannot complete the callback, return to that connection and retry the ordinary sign-in. Never paste tokens into support evidence. A local AEM sign-in is not SaaS SSO qualification.

Remaining documentation gate. Approved live provider/account and final installed sign-in captures remain required.

W03​

Reconnect, expire, sign out and switch accounts​

Documentation: FULL. Before you start: Review pending work and verify which connection and principal owns it.

Procedure. Use the connection reconnect/sign-in action when NeedsLogin appears. After sign-in, confirm the original principal before resuming jobs. To sign out, use Log out for that connection. To switch accounts, finish sign-out and start the approved sign-in flow; inspect the new principal before issuing actions.

Expected result. Local edits survive expiry and sign-out. Work accepted for an earlier identity does not silently resume as another user.

Cancel, errors and recovery. If identity differs, retain the old work for recovery. Cancel login without affecting other sessions. After restart, check work and identity before retrying an unknown operation.
