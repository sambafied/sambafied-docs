Titles, metadata, folders and remote organization

Guide home · Coverage and gaps · Image plan

Development guide draft, reviewed 28 October 2026. Steps describe the approved contract and are conditional on the installed build advertising that capability. Product and target acceptance remain separate.

The Actions menu separates display metadata from repository paths. Change Title changes a label. Rename/move changes a path. Copy/duplicate creates another identity. Delete affects the remote object. Do not use these names interchangeably.

Folder schema applies typed metadata under a qualified adapter; a direct assignment does not automatically rewrite descendants. Native metadata parity remains separate from an Open in Web fallback. For all mutations, confirm the original target and inspect the resulting operation, including partial success and retained drafts.

W24​

Change a display title​

Documentation: FULL. Before you start: Have metadata permission for the selected canonical asset.

Procedure. Choose Change Title, inspect the current title and enter the proposed title. Review validation and the exact target, then apply and read back the visible result.

Expected result. A title update does not rename the filename or move the asset. Filename/path changes use a separate workflow.

Cancel, errors and recovery. Cancel preserves the title. A permission/revision error retains the draft for review; do not assume two different metadata title fields synchronize automatically.

W25​

Edit metadata​

Documentation: FULL. Before you start: Use a qualified typed metadata editor for the selected target/schema.

Procedure. Open Edit metadata. Inspect required, multivalue and read-only fields. Make changes, review validation and save against the observed revision. Reopen/read back the intended fields after completion.

Expected result. Dirty drafts survive a stale update for comparison. A successful form submit is not proof every field was accepted.

Cancel, errors and recovery. Keep the draft when access changes or the revision is stale. If the native editor is unsupported, use the qualified AEM web route and record the desktop parity gap.

W26​

Create a folder and inspect properties​

Documentation: FULL. Before you start: Have create permission on the chosen parent.

Procedure. Choose Create DAM folder and enter a valid name/title. Inspect the final repository segment and any optional schema. Apply the review. Open Current/Selected folder properties to inspect the resulting identity and typed values.

Expected result. A folder created successfully with a later schema failure is partial success, not a reason to delete the folder.

Cancel, errors and recovery. Cancel before creation is a no-op. Distinguish existing name, missing parent and permission denial. Keep a partial result and use its explicit repair review.

W27​

Apply or remove a folder schema​

Documentation: FULL. Before you start: Have a qualified schema operation and the current folder revision.

Procedure. Open the folder schema action. Compare its current assignment with the intended schema or removal. Inspect scope and permissions before applying. Read back the assignment and any partial result.

Expected result. A direct assignment does not promise inherited or recursive changes to children.

Cancel, errors and recovery. Cancel keeps the draft/current assignment. For a failed W26 schema step, use an explicit new repair and retain the original outcome record.

W28​

Copy or duplicate an asset​

Documentation: FULL. Before you start: Review a destination on the same qualified server/connection.

Procedure. Choose Copy/Duplicate. Inspect the proposed new identity/name and destination. Review which metadata, renditions, references and versions the adapter will preserve. Approve the plan and inspect its destination result.

Expected result. The original remains. A duplicate is not an alias and does not inherit checkout ownership or ACLs by assumption.

Cancel, errors and recovery. Cancel leaves the source untouched. If native copy is unavailable, refuse or use an explicitly different export/import workflow; do not hide that difference.

W29​

Move or rename a filename​

Documentation: PLACEHOLDER. Before you start: This is a planned/capability-gated contract, not an installed acceptance claim.

Procedure. Review the current canonical identity, destination and affected descendants/references. Reject cross-connection, root-escape, self and descendant destinations. When a qualified action is available, approve only the reviewed plan and inspect source and destination afterward.

Expected result. Supported identity preservation must be proved; multi-item moves are not assumed atomic.

Cancel, errors and recovery. Retain uncertain outcomes for inspection. Never emulate a move by deleting before copying. Exact released control labels and native linked-document acceptance are pending.

Remaining documentation gate. Released control route, complete implementation and end-to-end acceptance need confirmation.

W30​

Delete remote assets or folders​

Documentation: PLACEHOLDER. Before you start: This is a planned/capability-gated contract. Obtain explicit remote-delete authority.

Procedure. Review selected remote identities, descendant counts, local dirty/open files and affected references. Resolve or preserve local work before confirming a tombstone for that exact plan. Inspect per-item remote outcomes.

Expected result. Remote deletion is different from discard, unpin and cache clear. A failed list or missing row never proves deletion.

Cancel, errors and recovery. Cancel before acceptance leaves remote data intact. After a partial delete, cancellation does not restore successful items. Final installed delete journey is not yet documented as usable.

Remaining documentation gate. Released UI, original-context safety and native/server acceptance remain required.
