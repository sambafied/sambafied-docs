Titles, metadata, folders and remote organization

Guide home · Find a task

Development preview. This guide describes work in progress, not a supported customer release. Follow a procedure only when its controls are available in your build. Availability depends on the server and your permissions.

Display title, filename and server location are different properties. Copy creates a new asset; a collection refers to an existing one. Check the affected asset and destination before changing anything.

A folder metadata schema defines available fields. Assigning a schema does not necessarily change descendants. Inspect any partial result and preserve drafts when an update fails. Use Open in Web where desktop editing is unavailable and permitted by your administrator.

Change a display title​

Have permission to change asset metadata.

  1. Choose Change Title.
  2. Inspect the current title and enter a new one.
  3. Review validation and save.
  4. Reopen details to check the result.

Changing a title does not rename or move the file.

Cancel to keep the title. If permissions or server changes prevent saving, keep the draft and refresh before trying again.

Edit metadata​

Metadata editing depends on the server and available form.

  1. Choose Edit metadata.
  2. Inspect required, multiple-value and read-only fields.
  3. Make changes and review validation before saving.
  4. Reopen details to check saved values.

Check the displayed result after submission.

Preserve your draft if the asset changed or access was denied. Use Open in Web if desktop editing is unavailable and your administrator permits it.

Create a folder and inspect properties​

Have permission to create a folder in the selected parent.

  1. Choose Create DAM folder.
  2. Enter its name and title; inspect the final name and optional metadata schema.
  3. Review and confirm creation.
  4. Open folder properties to inspect location and metadata.

Folder creation may succeed even if a later metadata step fails.

If the name exists, parent is missing or access is denied, correct that issue first. Keep a successfully created folder and repair metadata separately.

Apply or remove a folder schema​

A metadata schema defines folder fields. Have permission to change its assignment.

  1. Open the folder schema action, when available.
  2. Compare the current schema with the one you want to apply or remove.
  3. Review the affected folder and confirm.
  4. Reopen properties to inspect the result.

Changing a schema does not necessarily change descendants.

Cancel to retain the assignment. If assignment failed after folder creation, repair the existing folder rather than recreating it.

Copy or duplicate an asset​

Choose a supported destination on the same server connection.

  1. Choose Copy or Duplicate.
  2. Review destination and proposed name.
  3. Check which metadata, renditions, references and versions will be copied.
  4. Confirm and inspect the new asset.

The original remains. The copy is a separate asset with its own editing and access state.

Cancel to leave the source unchanged. If server copy is unavailable, export/import is a different procedure with different results.

Move or rename a filename​

Moving and filename renaming are planned; a supported customer procedure is not available yet.

  1. Keep the original asset and local edits in place.
  2. If your administrator offers an approved AEM web procedure, check pending edits, references and destination permission first.
  3. After an approved server change, refresh the desktop view and check linked documents.

Changing a display title differs from renaming a filename.

Do not rename cache entries as a substitute. Keep a safe copy and contact support if references are affected.

Delete remote assets or folders​

Remote deletion is planned; a supported customer procedure is not available yet.

  1. Review the asset or folder and preserve unuploaded work.
  2. Check descendants and references with your administrator.
  3. Use only an approved server deletion procedure, if available for your deployment.

Server deletion affects other users. It differs from clearing a local download or removing collection membership.

Cancel if scope or recovery is unclear. Do not delete work-folder files to attempt server deletion.
