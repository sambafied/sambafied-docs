Getting started

The public product is coming soon. These instructions are for developers and evaluators who want to build Sambafied from source. A production installer and supported compatibility matrix are not yet available.

Read readiness and limits before connecting. This guide describes evaluation preparation, not a production installation procedure.

System requirements​

Sambafied DAM Client is built in Rust and currently supports:

PlatformStatusNotes
Windows 10/11 (x64)Primary development targetRequires Cloud Files API support (NTFS volume)
Linux (x64)SupportedRequires FUSE3, GTK4 and libadwaita for the file browser
macOSNot yet qualifiedLinux and Windows are the current focus

Build requirements:

  • Rust toolchain (edition 2024) via rustup
  • On Windows: Visual Studio Build Tools with C++ workload
  • On Linux: FUSE3 development headers, GTK4, libadwaita

Build from source​

Clone the repository and build the desktop client:

git clone https://github.com/sambafied/sambafied.git
cd sambafied
cargo build --release -p sambafied-desktop

On Linux, to include the GTK file browser window:

cargo build --release -p sambafied-desktop --features files-browser

The binary is at target/release/sambafied-desktop (Linux) or target\release\sambafied-desktop.exe (Windows).

Windows: connect to a network share​

On Windows, use sambafied-desktop to map an SMB share:

sambafied-desktop connect --drive S --share \\server\share --prompt
sambafied-desktop status

The --prompt flag opens the Windows credential dialog. To disconnect:

sambafied-desktop disconnect --drive S

The watch command runs the background agent for Explorer integration:

sambafied-desktop watch

Linux: cloud profile and FUSE mount​

On Linux, create a login configuration JSON file and authenticate:

sambafied-desktop cloud-login --config /path/to/config.json --profiles-parent ~/.local/share/sambafied/profiles

Then mount using FUSE:

sambafied-desktop fuse-mount --config /path/to/config.json --mountpoint ~/SambafiedMount

The present command shows the file window or opens the last mounted share:

sambafied-desktop present

Desktop flow​

The implemented desktop flow accepts an Author URL and opens the sign-in page. After a successful connection, the agent owns the session and work folder. Sign-in, mount, original recall, logout and remembered restore have bounded local evidence.

A local sign-in result does not qualify your organization's SSO setup or an AEM as a Cloud Service session.

Verify the workflow​

  1. Open the work folder in Explorer (Windows) or the file browser (Linux).
  2. Navigate to a known test original and open it.
  3. Check the content against the known source.
  4. Record errors and status; an icon alone is not evidence that bytes transferred correctly.

Do not use a local save as proof that a remote upload succeeded. Publication and sync have separate behavior and qualification boundaries.

End the evaluation deliberately​

On Windows, disconnect the mapped drive:

sambafied-desktop disconnect --drive S

On Linux, unmount the FUSE filesystem or stop the running mount process.

Stopping and unregistering are different. Read the folder lifecycle before removing a registration. Preserve any local edits and uncertain publication state for review.

If a step fails, use troubleshooting. Avoid repeatedly creating replacement roots or deleting retained state.
